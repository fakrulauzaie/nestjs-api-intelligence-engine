# Backend API Intelligence Reference Fixture

## Purpose

This application is the frozen Phase 0 reference fixture for the Backend API
Intelligence MVP. It is deliberately small, uses one NestJS application and one
`tsconfig.json`, and contains both supported patterns and close negative cases.

The hand-authored ground truth lives in `expected/`. These files describe intended
static-analysis results; they are not generated by the application and must not be
changed merely to match analyzer output.

## Frozen implementation decisions

| Decision | Phase 0 choice |
|---|---|
| Runtime | Node.js 22.13 through 24.x; local tooling may invoke either installed runtime |
| Package manager | pnpm 11.x; retain the checked-in lockfile |
| Analyzer TypeScript | Pin exactly 5.9.3, matching the resolved fixture dependency |
| CLI parsing | Node.js `util.parseArgs`; no CLI framework initially |
| Runtime schema validation | Zod, exact version locked during Phase 1 |
| Test runner | Vitest, exact version locked during Phase 1 |
| Default `tsconfig` | `<repository>/tsconfig.json` |
| Default TypeORM table rule | Lowercase the entity class name; `Note` becomes `note` |
| Evidence paths | Repository-relative with `/` separators |
| Evidence coordinates | One-based lines and columns |
| Evidence snippet limit | 240 Unicode code points |
| Source-file size limit | 1 MiB by default, configurable downward or upward |
| Maximum call depth | Configurable from 1 to 3; default 3 |

The default table rule intentionally does not reproduce custom TypeORM naming
strategies. Explicit `@Entity('table_name')` always wins.

## Selected evaluation endpoints

The complete supported catalogue contains seven endpoints. These five are frozen for
manual evaluation:

| Role | Endpoint | Expected terminal |
|---|---|---|
| No-database baseline | `GET /` | `AppService.getHello`, no table |
| Clean read | `GET /notes` | `READ note` via `Repository<Note>.find()` |
| Clean write | `POST /notes` | `WRITE note` via `Repository<Note>.save()` |
| Directly guarded write | `DELETE /notes/:id` | `WRITE note` via `delete()` |
| Messy direct-repository path | `PUT /notes/legacy/:id` | `READ note` and `WRITE note` |

Two additional supported endpoints exercise a simple const route and combined
controller/method guards:

- `GET /notes/archived`
- `GET /admin/notes/count`

## Supported positive cases

- Empty controller and method paths.
- Controller prefix plus empty or literal method paths.
- Simple `const` string method path.
- Class-based constructor injection.
- Controller-to-service and service-to-service direct calls.
- `@InjectRepository(Note)` in a controller and a provider.
- TypeORM `find`, `findBy`, `count`, `save`, and `delete` operations.
- Default `@Entity()` and explicit `@Entity('audit_log')` table mappings.
- Method-level `@UseGuards`.
- Controller-level plus method-level `@UseGuards` on one endpoint.

## Deliberate unsupported and negative cases

- `COMPUTED_STATUS_PATH` is computed with `join()` and must produce
  `NEST_ROUTE_DYNAMIC`; `NotesController.computedStatus` must not become an endpoint.
- `LegacyNotifierService` uses a string-valued `@Inject` token and must produce
  `DI_TOKEN_UNSUPPORTED`; it must not become a class injection relationship.
- `NotesService.unsupportedPreload` calls `Repository.preload()` and must produce
  `TYPEORM_OPERATION_UNSUPPORTED`; it must not create a table read/write assertion.
- `NotesService.findAllBackup` is intentionally similar to `findAll`, but no controller
  calls it. Name similarity must not create a call edge.
- `LegacySink.write()` is not a TypeORM repository operation even though its name
  sounds like a write.
- `save()` calls prove a table write but not exact written columns.
- No absence of direct guards proves that an endpoint is public.

## Call-cycle decision

A source-level circular NestJS constructor dependency normally requires `forwardRef`
or another token form, both outside the MVP's supported class-only DI rules. Therefore
the integrated application does not contain an artificial broken circular dependency.
Cycle termination will be frozen and tested at the assertion-graph level in Phase 7,
where a synthetic `METHOD_CALLS_METHOD` cycle can test traversal without expanding DI
scope.

## Analyzer safety contract

The future analyzer may read this directory and create a TypeScript `Program` with
`noEmit`, but it must never:

- import or require application modules;
- call `bootstrap()`;
- run NestJS;
- invoke package scripts;
- compile or emit the fixture;
- connect to SQLite.

Developer-only fixture verification may typecheck or test the app independently of an
analyzer run. Such commands are not part of the analyzer pipeline.

## Ground-truth files

```text
expected/
  analysis.json
  endpoint-catalogue.json
  read-trace.json
  write-trace.json
  guarded-write-trace.json
  legacy-read-write-trace.json
  diagnostics.json

```

`analysis.json` is a Phase 0 semantic expectation, not the final canonical output
schema. Phase 2 will freeze stable IDs and runtime schemas, after which a generated
canonical golden file can be reviewed against this source-independent ground truth.
